# 文字列だけで付く点数の測定(2026年11月11日)

> 実装前に、通信なしで評価できるルールだけで点数を付け、悪性と正常でどの程度の差が出るかを測った記録です。
> 目的は、`docs/phases.md`のフェーズ5「判定を主機能のままにするかの判断」の基準を決める材料にすることです。
> 節番号(6.3など)はPLAN.mdの節を指します。スクリプトは`tools/eval/phase0/string_score.py`、出力は`tools/eval/phase0/results/string_score.txt`にあります。

## 方法

- **データ**:`docs/research/phase0.md`と同じ。悪性はJPCERT/CCのリスト(2026年7〜9月分、8,282件)、正常はCrUXの日本の一覧(2026年9月分)の「50万〜100万位」と「上位1万」。2026年11月11日に取得し直した
- **評価したルール**(配点は6.5の既定。暫定を含む):`keyword`、`random_label`、`random_subdomain`、`long_label`、`path_keyword`、`brand_contains`、`brand_lookalike`、`brand_in_path`、`abused_tld_high`、`abused_tld_moderate`、`abused_hosting`。グループの扱い(`name`は上限+3、`brand`は最大値のみ)も6.5に従った
- **評価していないルール**(通信が必要):新しさ(登録日、証明書)、`no_mx_spf`、`fast_flux`、`hold`、減点(`age_ge_5y`、`dnssec`)
- **この測定のために仮に決めたもの**(PLAN.mdでは未定。仕様として決めたものではない)
  - ブランドリスト:`docs/research/phase0.md`の集計で使った上位10ブランドと、その公式ドメイン(スクリプトの`BRANDS`)
  - 不審キーワード:6.3に例示された8語。照合はブランドと同じ長さのルール(5文字以上は部分一致)
  - `long_label`:1つのラベルにハイフンが3個以上、または30文字以上

## 読み取れること

1. **文字列だけで「要確認」に届くのは、悪性の約27%**。正常側は0.3〜0.6%で、該当した場合の差は大きいが、拾える範囲は狭い
2. **悪性の約28%は文字列では0点**(登録ドメインだけで見ると約46%)。この層は、登録日・DNS・証明書のルールでしか拾えない
3. **2点以上は悪性の約59%、正常の4〜5%**。「登録から1年以内」の新しさ(`age_31_365d`+1、`term_le_1y`+1)と合わせると「要確認」に届く層で、スコアの成績は、この層を登録日でどこまで拾えるかに左右される
4. **ホスト名の`keyword`は差が無い**(悪性1.0%、正常0.5〜1.1%)。パスの`path_keyword`は悪性で9.7%あるが、正常側が未測定のため判断できない
5. **`brand_lookalike`は最も高い配点(+4)だが、差が無い**(悪性0.2%、正常0.1〜0.5%)。正常側で該当した単語は`cloud`(`icloud`と距離1、352件)、`maison`(`saison`、54件)、`apply`(`apple`、43件)、`pass`(`vpass`、42件)など。仮のブランドリストでの結果だが、ブランドリストを決めるとき(12章の1)に、`exclude_words`で防ぐ対象として確認する
6. `brand_contains`は該当率は低い(7.1%)が、正常側との差は大きい(0.1〜0.2%)

### 参考の試算(仮定を含む)

フェーズ0の測定では、悪性37件のうち25件(68%)が登録から1年以内だった。文字列の点数と登録日が独立だと仮定すると、「要確認」に届くのは次の合計で**約5割**になる(DNSと証明書のルールを除く)。
- 文字列だけで4点以上:27%
- 文字列が2〜3点(31%)で、登録から1年以内(68%):約21%

実際には文字列の特徴と登録日は独立ではない(一括登録のドメインなど)ため、この値は目安にとどまる。全体の成績はフェーズ5で測る。

## 結果を読むときの注意

- **良く出やすい**:悪用の多いTLDの一覧、ランダム文字列の定義、上位10ブランドは、この悪性データをもとに選んだものである。同じデータで測っているため、別の時期のデータでは差が小さくなり得る
- **正常側は人気のあるサイトの一覧**で、利用者が不審に思って調べる「難しい正常データ」(最近登録された正規のドメイン、悪用の多いTLD上の正規のサイトなど)ではない。誤検知率は実際の運用より低く出る
- 悪性と正常でデータの出どころが違う(通報されたURLと、よく訪れられるサイト)
- ホスト単位の集計は、同じ登録ドメインの使い回し(サブドメインだけが違うホスト)を含む
- ブランドリスト、公式ドメイン、不審キーワードの照合方法は仮のもので、実装時に決める内容(12章の1)で結果が変わる

## 基準への使い方

- **上位サイトでの誤検知率の基準(5%以下)の裏付け**:文字列だけで4点以上は0.3〜0.6%、3点以上は2.8〜3.3%。3点の対象は、ほかのルールが1点付くと「要確認」になる。全体のスコアで5%を超える場合は、文字列以外のルール(`recent_cert`、`no_mx_spf`など)が正常側で多く該当していることを意味する
- **再現率の基準を絶対値で置かない理由**:「登録から1年以内」という単純なルールだけで悪性の約68%を拾える見込みがあり、文字列だけのスコアは約27%にとどまる。スコアに意味があるかは、単純なルールと比べて決める(`docs/phases.md`のフェーズ5)
