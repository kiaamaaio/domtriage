# 実データの事前調査(フェーズ0)の結果

> PLAN.mdの「2.1 実データの事前調査の結果」から、測定データの部分を移したものです。内容は変えていません。ただし移したあとに、次の4点を直しました:PLAN.mdの2.1と重複していた結論の段落の削除、`.co`・`.me`・`.cn`のWHOISフォールバックの判断の`docs/decisions.md`への移動、privateサフィックス上の測定の説明の修正(測り直しで確認)、測り直しの記録の追加。
> 本文中の節番号(6.3など)はPLAN.mdの節、「フェーズN」は`docs/phases.md`のフェーズを指します。
> 測定に使ったスクリプトは`tools/eval/phase0/`にあります。
> 結論と、それによる計画の変更はPLAN.mdの2.1にあります。

**データ**:JPCERT/CCがGitHubで公開しているフィッシングURLのリスト(`JPCERTCC/phishurl-list`)の2026年7〜9月分、8,282件(登録ドメイン4,204件)。2026年11月9日に取得・集計。

| 項目 | 結果 | 計画への影響 |
|---|---|---|
| gTLD/ccTLD | URL単位でgTLDが81.7%、ccTLDが18.3%(`.co`、`.cc`、`.cn`、`.me`が中心。`.jp`は0.4%) | gTLDはRDAPの提供が必須のため、登録日が取れない(信頼度:低)対象は少数の見込み。ccTLDの対応状況は下記の未確認事項 |
| TLDの偏り | 登録ドメイン単位で`.com`が56%、次いで`.help`(11%)、`.info`(9%)、`.top`(8%)、`.me`、`.cn`、`.shop`、`.cfd`、`.icu`など | 「悪用の多いTLD」ルールを追加(6.3)。ただし`.com`が過半なので、単独では決め手にならない |
| ホスト名にブランド名を含む | 偽装先が上位10ブランドであるURL(全8,282件のうち6,615件、79.9%)で集計。URL単位9.0%、登録ドメイン単位16.1% | **ブランド偽装の判定が効くのは一部**。基本的な照合は残し、精巧な判定(同形異字)は後回しにする |
| IDN(国際化ドメイン) | **0件**(8,282件中) | 同形異字の判定とconfusables表はフェーズ5以降に必要性を再判断する |
| 登録ドメインがランダムらしい | 登録ドメイン単位で約37%(母音が少ない、子音が5連続以上、数字を含む、などの簡易判定)。正常側との比較は下記 | **ランダム文字列の判定の重要度が高い**。登録ドメインとサブドメインで別のルールにする |
| サブドメインの先頭がランダムらしい | URL単位で15.6% | 同上 |
| privateサフィックス上 | URL単位で4.6%。大半が`duckdns.org`とAmazon S3(`s3.*.amazonaws.com`)で、`github.io`・`pages.dev`等はほぼ無い | `abused_hosting`の既定の一覧をデータに合わせる |
| URLのパス | パスあり81%、うち不審キーワードを含むのはURL単位で約9%、ブランド名を含むのは2.5% | パスの判定は寄与が小さい見込み。実装は軽いので残すが、期待しすぎない |
| 登録ドメインの使い回し | 1ドメインあたり平均2.0件、多いものは数百件 | 照会結果のキャッシュ(6.1)が有効 |

**ccTLDのRDAP対応(2026年11月9日、計画者の手元で確認)**
- bootstrapに載っていたのは`.cc`のみ。**`.co`、`.me`、`.cn`は未掲載**(`.jp`も未掲載。6.1参照)
- これを当てはめた、登録日が取れるかどうかの見込み:

| 区分 | 登録ドメイン単位 | URL単位 |
|---|---|---|
| RDAPで登録日が取れる見込み(gTLD・`.cc`) | 92.2% | 82.8% |
| RDAP非対応(`.co`、`.me`、`.cn`) | 6.1% | 11.9% |
| `.jp`(WHOISで補える) | 0.7% | 0.4% |
| その他のccTLD(未確認) | 0.5% | 0.3% |
| privateサフィックス上(登録日は評価不可) | 0.5% | 4.6% |

- 「信頼度:低」になる対象は、登録ドメイン単位で**約7%**、URL単位で**約17%**の見込み。URL単位で多いのは、少数の`.co`ドメインが大量に使い回されているため(例:1ドメインで300件以上)
- `.co`・`.me`・`.cn`のWHOISフォールバックを今回は追加しない判断は`docs/decisions.md`にある

**報告時点での登録からの日数(2026年11月9日、計画者の手元で測定)**

9月分から無作為に抽出した40の登録ドメイン(privateサフィックス上を除く)について、RDAPの登録日と、リストに初めて載った日の差を求めた。取得できたのは37件(残り3件は404。うち2件は`eki-net`を含む`.help`のドメインで、報告から約2か月で既に削除されていた)。

| 登録からの日数 | 件数 | 割合 |
|---|---|---|
| 7日以内 | 2 | 5% |
| 8〜30日 | 2 | 5% |
| 31〜180日 | 2 | 5% |
| **181〜365日** | **19** | **51%** |
| 1〜2年 | 3 | 8% |
| 2〜5年 | 7 | 19% |
| 5年超 | 2 | 5% |

- 中央値は308日。**登録から30日以内は約1割**にとどまり、半年〜1年前に登録したドメインを寝かせてから使う例が主流
- 同じ日に登録された似た名前のドメインがある(例:2025-11-23に`tmsvr.info`、`kvqlv.info`、`ockvv.info`、`hsije.info`)。一括登録の跡と考えられる
- 2年以上前の登録が24%あり、期限切れのドメインの取り直しや転用と考えられるもの(ピンイン風の名前など)を含む
- ブランド名を含むドメインは早く削除される傾向があり、**後から検証すると実際より少なく見える**
- 標本は40件と少ないため、傾向の把握にとどめ、配点はフェーズ5で大きなデータで決め直す

**正常なドメインとの比較(2026年11月9日、計画時に集計)**

フィッシング側の該当率だけでは区別に効くか判断できないため、正常側として、日本のChrome利用者がよく訪れるサイトの一覧(CrUX。GitHubの`zakird/crux-top-lists`、2026年9月分)に同じ判定をかけた。小規模な正規サイトに近い「50万〜100万位」(約40万の登録ドメイン)を主な比較対象とし、上位1万も参考にした。

*ランダム文字列(登録ドメインのラベル)*

| 判定の方法 | フィッシング | 正常(50万〜100万位) | 正常(上位1万) |
|---|---|---|---|
| A:簡易(数字を含むだけでも該当) | 40.3% | 10.5% | 12.7% |
| B:5文字以上で、母音が20%未満か子音が5連続(ラベル全体で判定) | 27.6% | 3.5% | 3.7% |
| **B':Bをハイフンで区切った単語ごとに判定し、Punycodeを除外**(採用。定義は6.3) | **27.5%** | **2.7%** | 3.0% |
| C:Bに加え、6文字以上の英数字混在 | 33.7% | 7.4% | 7.1% |

- 上の表のA〜Cは初回の集計、B'は6.3の定義を確定したあとの測り直し(2026年11月9日)。B'の数字が実装に引き継ぐべき値
- サブドメインの先頭ラベル(`www`を除く)では、B'がフィッシング32.9%、正常3.7%。6.3の定義(サブドメインのラベルの**いずれか**が該当すれば該当)でホスト単位に測り直すと、フィッシング33.7%(3,731ホスト)、正常3.7%(50万〜100万位、108,509ホスト)、3.4%(上位1万)で、先頭のラベルだけの場合とほぼ同じだった(ラベルが2つ以上あるホストは少ないため)。ただし、メールのクリック計測用のホスト名など機械的な名前の正規サブドメインはCrUXにほぼ入らないため、**正常側の該当率は実際より低く出ている**と考えられる
- B'では`smbc`、`kddi`、`mufg`、`jcb`などの子音の多い略語は該当しない(Aでは`smbc`が該当)。`x-trend`もB'では該当しない
- **既知の誤検知**:母音の少ない普通の英単語(`script`、`crypto`、`twitch`、`strength`、`french`、`rhythm`、`sports`)が該当する。正常側の該当例にも`nagahama-sports`のように「sports」だけで該当したものが含まれていた。また、測り直しの際に**Punycode(`xn--`で始まるラベル)が該当**することがわかったため、判定から除外する(6.3)
- **方法Bの限界**:一括登録の4件のうち、該当するのは`tmsvr`と`kvqlv`の2件のみ。`ockvv`(母音がちょうど20%)と`hsije`(母音40%)は該当しない
- B'の数字は、参照実装にPunycodeの除外を入れたうえで測り直した値(除外前は正常側2.9%。50万〜100万位の`xn--`のラベル1,316件のうち671件が該当していた)。この測り直しは別のセッションのレビューで再現・確認されている
- **privateサフィックスより左のラベル**(例:S3のバケット名、`duckdns.org`のホスト名。`www`を除く)の**いずれか**にB'を当てると、フィッシング54.9%(328ホスト)、正常4.4%(20,578ホスト)。正常側では`dqe0y0sqzkijh.cloudfront.net`のように、基盤が自動で付ける名前が該当する。このため、privateサフィックス上のラベルには弱いほうの`random_subdomain`を当てる(6.3)
- 2026年11月9日、単語の長さを英字と数字の合計で数えるように直した参照実装で、上記のB'の数字(登録ドメイン、サブドメイン、privateサフィックス上)を測り直し、数字は変わらなかった(データに出てくるラベル856,900種類のうち、修正前と判定が変わるものは0件)
- 測定に使ったスクリプトと判定の参照実装は`tools/eval/phase0/`に保存する(8章)
- 2026年11月11日、計画時のレビューを受けて、参照実装を「ASCII以外の文字を含むラベルは全体を判定しない」に直した(Unicodeで渡した場合とPunycodeで渡した場合の結果をそろえるため。`docs/decisions.md`)。測定データ(CrUXはPunycode、フィッシング側はIDNが0件)にはASCII以外を含むラベルが無いため、上記の数字は変わらない

**証明書の発行時期(2026年11月9日、計画者の手元で測定)**

上記の40ドメインについてcrt.shを照会した。

- **取得できたのは18件のみ。21件(52%)は取得失敗**、1件は証明書0件。所要時間は約20分(1件あたり約30秒)
- 18件のうち、**直近の証明書がリストに載る5日前以内に発行されていたのは15件(83%)**
- 初回の証明書がリストに載る7日前以内(`cert_lt_7d`)は5件(28%)。うち4件は**登録から7〜11か月寝かせたあと、使う直前に初めて証明書を取得**していた。これらは登録日が取れるため、当初の`--ct auto`(登録日が取れないときだけ照会)では照会を省いてしまう層だった
- 残りは初回の証明書がずっと前(前の所有者のものと考えられる。例:登録が2023年で初回の証明書が2011年)だが、直近の証明書は使う直前に発行されていた
- 正規のサイトも2か月前後ごとに証明書を更新するため、「直近の証明書が新しい」は正常側でも一定の割合(1割前後と推定)で該当し得る。**正常側の該当率は未測定**
